# 플랜두씨 다이어리 2 — 인증을 붙인 내 계획·실제 기록 (과제 7)

내가 세운 **계획**과 **실제로 한 일**을 나란히 적고, 차이를 돌아보며 다음 계획을 고치는 다이어리입니다.
6번에서는 링크를 아는 사람 누구나 볼 수 있었지만, 7번에서는 **가입·로그인을 붙여서 내 자료를 나만 볼 수 있게** 했습니다.
그리고 이 앱을 5일 동안 직접 쓰면서, 계획 규칙을 하나 바꿨을 때 결과가 어떻게 달라지는지 기록했습니다.

## 이어서 사용한 6번 결과 (과제 6 최종 제출)

- 6번 결과물: https://newpy15.github.io/plan-do-see-diary/
- 6번 소스(고정 커밋): https://github.com/newpy15/plan-do-see-diary/commit/f5693f5322600f9fc2ac25c941eac466221f3349
- 이 저장소의 이력에는 위 6번 커밋이 조상으로 그대로 들어 있습니다. 6번 사이트는 그대로 열립니다.

## 7번에서 달라진 것

| 6번 | 7번 |
|---|---|
| 링크를 아는 사람은 누구나 보고 고칠 수 있음 | **로그인한 본인의 자료만** 보고 고칠 수 있음 |
| 표를 누구나 읽고 쓸 수 있음 | 표는 아무에게도 직접 열려 있지 않고, **함수를 통해서만**, 요청한 사람의 자료만 다룸 |
| 로그아웃이 없음 | 로그아웃하면 서버가 로그인 값을 지워서 **이전 값은 바로 거절**됨 |
| — | **5일 기록** 탭: 질문·지표·단위, 날짜별 값, 규칙 변경 1회, 변경 전후 비교 |
| — | **내 계정** 탭: 내 자료 내보내기 · 6번 자료 가져오기 · 계정과 내 자료 삭제 |

## 사용 방법

1. 주소를 열면 **로그인 화면**이 나옵니다. 처음이면 `처음이에요, 가입하기`로 이메일과 비밀번호(8자 이상)를 정해 가입하세요.
2. 로그인하면 6번과 같은 탭들이 보입니다: `1 계획` → `2 할 일` → `3 실제로 한 일` → `4 돌아보기`. (사용법은 6번과 같습니다.)
3. **5 5일 기록**
   - 1일차: 5일 동안 알아볼 **질문 한 문장**, **관찰 지표 하나**, **단위**를 정하고 고정합니다. (첫 기록 뒤에는 바꿀 수 없습니다.)
   - 매일: 오늘 값을 기록합니다. 날짜는 서버가 한국 시간으로 정합니다. 같은 날 다시 적으면 그날 값을 덮어씁니다.
   - 2일차 기록을 남긴 뒤, 3일차 기록 전에 **계획 규칙을 하나 바꾸고** 이유를 적습니다. (한 번만 가능, 바꾼 시각은 서버가 기록)
   - 변경 전·후를 **같은 지표·같은 단위·같은 계산 규칙**으로 비교한 표가 자동으로 나옵니다.
4. **6 내 계정**: 로그아웃 / 내 자료 파일로 내려받기 / 6번에서 내려받은 파일을 내 계정으로 가져오기 / 계정 삭제(내 자료도 함께 삭제).

## 짧은 확인 방법

1. **어디로 가나요**: 결과물 URL을 새 시크릿 창에서 엽니다. (계정을 만들지 않아도 로그인 화면까지는 열립니다.)
2. **무엇을 하나요 (3단계)**: ① 주소 끝에 `#todo`를 붙여 열어도 자료 대신 로그인 화면이 나오는지 본다 → ② `docs/auth-check-result.md`(내가 직접 돌려서 남긴 확인 기록)를 연다 → ③ 그 기록의 "남의 자료 건드리기"와 "로그아웃 전·후" 표를 본다.
3. **무엇이 보이면 통과인가요**: 로그인 없이는 자료가 하나도 안 보이고, 확인 기록에서 남의 자료 읽기·고치기·지우기가 모두 거절(404/401)이며, 로그아웃 뒤 같은 요청이 401로 거절되어 ✅만 있습니다.
4. **안 될 때는 무엇이 보이나요**: 화면 위쪽에 빨간 안내가 나옵니다. "DB 접근이 거부되었습니다"는 DB 설정 문제, "이메일 또는 비밀번호가 맞지 않습니다"는 입력 오류, "로그인이 필요하거나 이미 끝났습니다"는 다시 로그인하라는 뜻입니다.

## AI와 내 판단

- **AI에게 맡긴 일**: 로그인 연결 코드, 내 자료만 보이게 하는 DB 규칙, 확인 스크립트, 설명서 초안 작성을 AI(Claude)에게 맡겼습니다.
- **내가 직접 판단한 일**: 6번을 이어서 7번을 만들되 6번 사이트는 그대로 두기로 했고, 새 프로젝트를 만들지 않고 6번과 같은 Supabase 프로젝트를 쓰기로 했습니다. 5일 동안 알아볼 질문·지표·바꿀 규칙은 AI가 후보 3개를 제안했고 내가 1번(하루 운동 시간, 30분→20분)을 골랐습니다. 가입 보안 설정(이메일 확인 끄기)은 내가 직접 바꿨습니다.
- **AI 말을 안 들은 일**: AI는 7번용 Supabase 프로젝트를 새로 만들자고 했지만, 같은 프로젝트 안의 별도 칸(`diary2`)을 쓰는 쪽으로 바꿨습니다.

## 직접 다시 만들려면

1. Supabase 프로젝트의 **SQL Editor**에 `supabase.sql` 전체를 붙여 넣고 Run합니다. (여러 번 실행해도 안전하고, 같은 프로젝트의 `public` 칸에 있는 다른 자료는 건드리지 않습니다.)
2. **Authentication → Sign In / Providers**에서 `Confirm email`을 끕니다.
3. `index.html` 위쪽의 `SUPABASE_URL`, `SUPABASE_KEY`에 공개용(publishable) 키를 넣습니다. 관리자용 비밀 키는 넣지 마세요.
4. GitHub Pages로 `main` 브랜치 `/ (root)`를 공개합니다.
