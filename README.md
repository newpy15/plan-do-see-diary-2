# 플랜두씨 다이어리

**내가 세운 계획**과 **실제로 한 일**을 나란히 적어 두고, 그 차이를 돌아보면서 **다음 계획을 고치는** 작은 다이어리 웹페이지입니다. (과제 6)

> 지금은 로그인이 없어 링크를 아는 사람은 누구나 볼 수 있습니다. 남이 봐도 괜찮은 내용만 넣으세요
> (잠그는 일은 7번 과제에서 합니다.)

## 왜 만들었나요?

할 일을 체크하고 끝내는 앱은 많지만, 내가 계획을 **어느 쪽으로 자주 틀리는지**는 잘 보이지 않습니다.
예를 들어 "30분이면 되겠지" 했는데 실제로는 1시간이 걸렸다면, 다음 계획은 그만큼 넉넉하게 세워야 합니다.
그래서 남이 만든 예시가 아니라 **내 계획과 내 기록**을 직접 넣고, 돌아보기에서 얻은 결론을 **다음 계획에 한 줄로 넘기는** 흐름으로 만들었습니다.

```
계획 세우기(Plan) → 실제로 한 일 적기(Do) → 돌아보기(See) → 다음 계획에 반영
```

내용은 인터넷의 데이터베이스(Supabase)에 저장되므로, 새로고침하거나 다른 기기에서 열어도 그대로 남아 있습니다.

## 사용 방법

위쪽의 탭 4개를 왼쪽부터 순서대로 쓰면 됩니다.

### 1 계획 — 계획 세우기
1. 계획 이름, 종류(운동·공부·업무·게임 연습·ALEPH·기타), 시작일과 끝나는 날을 적습니다.
2. 우선순위, 예상 시간(분), **성공 기준**(어떻게 되면 성공인지)을 적고 **계획 만들기**를 누릅니다.
3. 계획을 **고치기**로 바꿔도 걱정하지 마세요. 고치기 전 내용은 **수정 이력**에 그대로 남습니다.

### 2 할 일 — 할 일 다루기
1. 위에서 만든 계획에 딸린 할 일을 추가합니다. (마감일, 우선순위, 태그, 예상 시간)
2. **시작**을 누르면 "진행 중", **완료**를 누르면 "완료"가 됩니다. 완료를 누르면 시작·끝 시각, 걸린 시간, 막힌 이유를 같이 적는 칸이 열립니다. 비워 두어도 됩니다.
3. 완료한 일은 **되돌리기**로 다시 진행 중으로 바꿀 수 있습니다.
4. 위쪽 칸으로 **검색**하고, 상태·우선순위·태그로 **거르고**, 마감일·우선순위 등으로 **정렬**합니다. 어떤 기준으로 정렬했는지는 목록 위에 글자로 적혀 있습니다.

### 3 실제로 한 일 — 실행 기록
1. 할 일을 고르고, 실제로 언제 시작해서 언제 끝났는지, 몇 분 걸렸는지, 어디서 막혔는지를 적습니다.
2. 이 기록은 **원래 계획 값을 바꾸지 않습니다.** (계획은 계획대로, 실제는 실제대로 남습니다.)
3. 같은 기록을 실수로 두 번 저장해도 1건만 남습니다.

### 4 돌아보기 — 계획과 실제 비교
1. 계획한 일 / 완료 / 지연 / 막힘 / 예상 시간 / 실제 시간 / 차이를 한눈에 봅니다. (차이 = 실제 − 예상)
2. 숫자를 누르면 **그 숫자가 나온 할 일과 기록**이 아래에 나옵니다.
3. "기간별 모아 보기" 표에서 계획(기간)마다 비교하고, 고칠 점 한 가지를 **다음 계획으로 넘길 한 줄**에 적습니다.
4. 지연은 "완료하지 않았고 마감일이 한국 시간 기준 오늘보다 앞선 일"입니다. 완료한 일은 지연으로 세지 않습니다.

### 내 자료 내보내기
화면 맨 위의 **내 자료 내보내기**를 누르면 계획·할 일·기록·수정 이력이 **파일 하나(JSON)** 로 내려받아집니다.

## 처음 들어 있는 자료

`(예시)`가 붙은 계획과 할 일은 처음 열었을 때 화면이 비어 보이지 않게 넣어 둔 것입니다. 지우거나 고쳐서 내 계획과 기록으로 쓰세요.

## 짧은 확인 방법

1. **어디로 가나요**: 공개 결과물 주소를 로그인 없이 새 시크릿 창에서 엽니다.
2. **무엇을 하나요 (3단계)**: ① `4 돌아보기`에서 숫자를 눌러 근거 기록을 본다 → ② `2 할 일`에서 할 일 하나의 `완료`를 두 번 눌러 본다 → ③ 새로고침한다.
3. **무엇이 보이면 통과인가요**: 숫자를 누르면 그 숫자만큼의 할 일·기록이 나오고, 완료 기록은 1건이며 완료 수는 1만 늘고, 새로고침 뒤에도 값이 그대로입니다.
4. **안 될 때는 무엇이 보이나요**: 위쪽에 빨간 안내가 보입니다. "DB 표·함수를 찾을 수 없습니다"가 보이면 `supabase.sql`을 아직 실행하지 않은 것이고, "DB 접근이 거부되었습니다"가 보이면 접근 정책 문제입니다.

## AI와 내 판단

- **AI에게 맡긴 일**: 화면 구성, 데이터베이스 설계(표·규칙·함수), 시험 코드 작성을 AI(Claude)에게 맡겼습니다.
- **내가 직접 판단한 일**: 서버를 따로 켜 두지 않고 GitHub 링크로 열리는 `index.html` 방식으로 가기로 정했고, 과제 조건을 다시 읽고 수정 계획을 먼저 보여 달라고 요구했습니다. 예시 자료는 페이지가 열린 뒤 내가 직접 입력하기로 했습니다.
- **AI 말을 안 들은 일**: AI가 처음 제안한 별도 서버 방식(Python 서버, Cloudflare)은 내가 원하는 방식이 아니라서 따르지 않았고, "내 자료·확인" 탭은 필요 없다고 판단해 앱에서 뺐습니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 전체 |
| `supabase.sql` | 데이터베이스 표, 규칙(완료 중복 방지, 수정 이력 등), 시작용 예시 자료 |
| `contracts/pds-schema-v2.json` | 표·항목·관계·날짜 규칙 설명 |

- 날짜와 시각은 UTC로 저장하고 화면에서는 한국(서울) 시간으로 보여 줍니다. 시간 단위는 분입니다.
- `index.html` 위쪽의 `SUPABASE_KEY`는 브라우저에 공개되어도 되는 **공개용 키**입니다. 관리자용 비밀 키는 이 저장소 어디에도 없습니다.

## 직접 다시 만들려면

1. [supabase.com](https://supabase.com)에서 프로젝트를 만들고, **SQL Editor**에 `supabase.sql`을 통째로 붙여 넣어 **Run**합니다. (여러 번 실행해도 안전합니다.)
2. **Project Settings → API**의 `Project URL`과 공개용(publishable) 키를 `index.html` 위쪽 `SUPABASE_URL`, `SUPABASE_KEY`에 넣습니다.
3. GitHub 저장소 **Settings → Pages**에서 `main` 브랜치 `/ (root)`를 공개합니다.
